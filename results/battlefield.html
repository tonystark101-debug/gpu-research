The old 74 was flattered: the simulator gave our core about 10× the bandwidth of a Jetson core, answering 4–5× sooner. A Jetson core should land near the A100 core's 223: it does the same AI maths per tick and gets slightly more memory per tick. That's an estimate until we test a real Jetson.

The fix is depth: let the copy engine keep 64 reads in flight instead of 8

Multiply-adds per clock tick, on the Jetson memory share, by how many memory reads the copy engine may have outstanding.

Why 8 is too few: 8 reads × 64 bytes ÷ 400 ticks = 1.3 bytes per tick, a tenth of what the memory can deliver. Past 64, something else becomes the limit. On the old fast memory the same change is worth only 1%, which is why we missed it.

Where our core's power goes: mostly clocking storage that isn't doing anything

Watts at 1 GHz, by how often each wire switches (synthesis on the ASAP7 7 nm-class library, before layout).

1.81 million flip-flops, clocked every tick Other logic

The biggest lever is clock gating: real GPUs switch off the clock to idle units, and this open-source flow doesn't. A third of the core's area is flip-flops, because register files are built from them instead of dense memory. Vortex's default power method gives 18 W. It assumes switching multiplies through the arithmetic to about 2 toggles per wire per tick, so we don't use it.

Work per watt, small matrix job: roughly 10× behind a Jetson core

Billions of operations per second per watt (GFLOPS/W), one core on a Jetson core's memory share. Bars show the range of the estimate.

Our core (copy engine 64 deep, 875 MHz, 2.5–4 W) Jetson core, estimated

The Jetson core's figure comes from two things. Its board's measured power under AI load is 18–22 W, of which we take 50–70% as the GPU's share, split 8 ways. Its work per tick is the A100 core's from our yardstick. The comparison flatters us: our core sits on a newer-class process and leaves out the shared cache and memory controllers.
